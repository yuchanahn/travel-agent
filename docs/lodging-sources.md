## 실제 읽기 검증

현재 프로젝트의 fetch_public_page·extract_page를 그대로 실행했다. 브라우저·로그인·쿠키·신규 크롤러를 사용하지 않았다.

- 여기어때 표본1개: HTTP200, 수신216787바이트, 추출2894문자. 객실 이름·표시금액·기준/최대 인원·추가요금·취소 안내가 포함됐다. 주소는 추출문에서 확인되지 않았다. 이름에 가평이 들어간다고 행정구역을 확정하지 않는다.
- 같은 페이지에 공개 검색 결과에서 관찰된 checkIn·checkOut·personal 파라미터로 2026-11-14~15·성인2명 조건을 넣었다. HTTP200, 수신225249바이트이고 Next.js query에 같은 값이 있었다. 요청 값 반영은 가격 적용·재고 검증과 다르다.
- 그 날짜 지정 URL을 기존 web_read에 전달하자2502바이트 패킷·page_fetched=true·truncated=true·verified_current=false로 읽혔다. 발췌이므로 페이지 전체 내용을 보존하지 않는다.
- NOL 표본1개는HTTP403으로 본문을 읽지 못했다. 내장 검색 도구에서 페이지가 보인 사실을 우리 HTTP 클라이언트의 수집 성공으로 표현하지 않는다.

객실 카드의 취소 라벨과 숙소 일반 환불 안내는 적용 대상이 다를 수 있다. 객실·요금제·날짜가 연결되지 않은 채 일반 안내를 특정 예약의 확정 취소규정으로 제시하지 않는다. 쿠폰 적용가나 페이지 기본 날짜의 금액도 사용자가 요청한 일정의 결제 총액으로 확정하지 않는다.

## 적용 방식

모델이 필요에 따라 site:yeogi.com 또는 site:nol.yanolja.com 같은 공개 검색을 선택하고, 등록된 출처를 web_read로 읽을 수 있다. 특정 사이트를 매번 강제 호출하거나 새로운 예약 전용 도구로 고정하지 않았다. 실제 모델이 그 경로를 선택하고 근거를 적절히 활용하는지는068의 여행 흐름 평가와 별개로 확인해야 한다.
