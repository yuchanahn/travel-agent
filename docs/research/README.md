# 연구일지

코드와 함께 검증 가능한 기록을 버전 관리한다. 노션에는 같은 작업의 맥락과 결론을 정리한다.

## 기록 단위

의미 있는 구현·실험·결정 단위로 작성한다. 날짜는 Asia/Seoul 기준, 파일명은 YYYY-MM-DD-NNN-topic.md다. 작은 명령마다 기록을 늘리지 않는다.

기본 흐름은 **쿼리·초기 답변 → 문제 정의 → 문제 분석 → 연구 과정 → 문제 해결 → 개선된 답변과 검증**이다.

1. 문제 정의: 실제 쿼리·초기 답변과 부족한 점, 좋은 답변의 판정 기준을 먼저 둔다.
2. 문제 분석: 검색·정정 반영·근거 사용·출력 형식 등 실패 원인을 실행 기록으로 좁힌다. 관찰과 가설을 구분한다.
3. 연구 과정: 참고 자료, 대안과 트레이드오프, 실험 조건·비교 기준, 실패한 시도를 기록한다.
4. 문제 해결: 선택 이유와 실제 코드·구조·흐름도를 보여준다. 구현과 제안을 구분한다.
5. 검증: 같은 쿼리의 개선된 답변, 실제 stdout/stderr, 지표, 회귀와 추가 비용, 남은 한계를 남긴다. 좋은 결과를 미리 가정하지 않는다.

실행 명령·시점·코드 버전·모델/문맥/thinking/fixture 조건·원본 파일 출처·노션 동기화 URL을 함께 기록한다. 원문 출력과 해석은 코드 블록 안팎으로 분리한다. stdout, stderr, 저장 JSON, trace를 정확히 표시하고 원문 발췌는 내용을 고치지 않는다. 과거 출력이 없으면 없다고 쓰며, 현재 재실행은 현재 검증으로만 표시한다. 기획·환경·정책 작업에는 가상의 모델 답변을 붙이지 않고 개발 요청과 확인 가능한 결과를 대응시킨다.

구현 기록에는 실제 소스의 코드 조각과 구조·데이터 흐름 다이어그램을 함께 넣는다. 파일·함수·기준 커밋을 표시하고 코드와 설계 이유를 연결한다. 의사 코드와 실제 구현, 인용 ID 검사와 의미적 사실 검증 등을 구분한다. 코드가 없는 변경은 해당 설정·문서의 변경 내용을 기록한다.

공개 원본 로그에 개인 정보가 섞이지 않도록 검토한다. 실패 사례와 점수는 유리한 결과로 덮어쓰지 않는다. 기존 Codex 경험에 대한 회고는 측정된 비교 실험으로 표시하지 않는다.

## 기존 기록 보강

001~009 앞부분에 위 문제 해결 흐름을 보강하고 작성 당시의 상세 기록을 보존했다. 001은 보존된 결과 JSON, 007은 당시 stdout 캡처, 009는 초기·실패 결과 JSON과 현재 재실행 stdout을 구분해 인용한다. 현재 재실행은 구현 커밋 e6fd0f5 기준이며 캡처 메타데이터·분리된 원본 stdout/stderr는 Git 제외 경로 `artifacts/research-evidence-2026-10-17/manifest.json`에 있다. 문서에 실은 출력은 공개 합성 데이터와 비민감 상태 확인으로 한정했다.

보강 검증: 원래 본문 9개 보존과 원본 파일에서 가져온 출력·코드·설정 발췌 18개의 일치를 확인했다. 노션도 9개를 다시 읽어 단계·기존 본문·문장과 값을 대조했다. 노션 렌더러의 공통 들여쓰기 정규화는 원본 파일의 바이트 변경과 구분한다. 현재 재실행은 상태 조회·설치 확인·코드 목록·단위 테스트26개와 합성 최신 예산 요청1개 및 trace 조회다. 기존9개 시나리오 전체를 이번에 재평가한 것으로 표시하지 않는다. 프로그램 실행 코드는 바꾸지 않았다.
