# 060: TourAPI 도입 취소와 MCP 범위 정리

2026-10-19

## 결정과 배경

059에서는 관광공사 국문 API 키 발급을 다음 단계로 제시했다. 사용자가 신청 과정의 신고 안내와 절차 부담을 이유로 도입하지 않기로 했다. TourAPI 연결·키 발급 후속을 취소한다. 해당 안내의 법적 적용 여부는 이번에 조사하지 않았으며, 모든 공개 API에 신고가 필요하다는 결론을 내리지 않는다.

## 문제 분석과 해결

MCP 프로토콜 연결과 특정 데이터 공급자의 이용 조건은 별개다. MCP 클라이언트는 이미 실제 stdio·HTTP 전송과 합성 모델 호출로 검증했으므로 기반을 유지한다. 기관 API 가입을 해야 프로젝트가 진행되는 구조로 두지 않는다.

- 현재 안내와 로드맵에서 TourAPI 키 발급을 다음 단계로 요구하던 내용을 수정했다.
- 호스트 비공개 설정에서 준비했던 tourism 항목을 제거했다. 공개 예시도 빈 servers 목록으로 바꿨다.
- Booking.com은 도입 계획에 넣지 않고 이전 후보 조사 이력으로만 남긴다.
- 기존 Brave 웹검색·본문 읽기·메모리·MCP 클라이언트 코드는 유지한다. 신규 API 가입 없이 사용할 다음 MCP 후보는 아직 정하지 않았다.

```json
{
  "servers": []
}
```

위는 examples/mcp-servers.example.json의 실제 변경 내용이다. 기준 ebee397 이후 이번 문서·설정 변경이며 에이전트 실행 코드는 수정하지 않았다.

## 확인한 결과

설정 로더로 확인한 활성 비공개 서버0개, 예시 서버0개다. 키 파일·외부 API 없이 빈 설정이 정상으로 읽힌다. 기존 clone과 실험 결과는 조사 이력으로 보존했다. 모델·외부 도구 호출은 없으므로 새 답변·툴콜 로그·성능 개선을 만들지 않는다. 실행 코드가 바뀌지 않아 전체 모델 평가나 Docker 재배포는 하지 않았다.

다음은 실제 여행 준비에서 부족한 정보를 기준으로 연결 대상을 정하는 것이다. MCP 숫자를 늘리기 위해 가입·신고가 필요한 공급자를 추가하지 않는다.
