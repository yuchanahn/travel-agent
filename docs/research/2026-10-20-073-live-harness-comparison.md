<callout icon="📌">

	당시 우리 검색은 Brave API 직접 호출, Claude Code 검색은 공식 Brave MCP였다. 우리 MCP에는 OpenBnB만 연결돼 있었다.
</callout>

## 무엇이 달랐나

| 질문 | 우리 에이전트 | Claude Code |
|---|---|---|
| 펜션 찾기 | 모델19회·도구18회. 상세 비교를 하겠다고 말하며 종료 | 모델5회·검색4회. 비교표와 링크 작성. 일부 주소·시설 확인 부족 |
| 수목원 안내 | 모델3회·도구2회. 공식 요금 페이지 본문 조회 | 모델2회·검색1회. 검색 발췌만으로 정리 |

**우리 쪽 문제:** 펜션 탐색이 행정구역·다른 지역 숙소로 샜다. 마지막 응답은384토큰이고 종료 사유는 stop이었다. 출력 한도4096에 잘린 것이 아니다.

**자료의 차이:** 공식 Brave MCP는 추가 검색 발췌(extra_snippets)를 전달했다. 우리 직접 검색기는 대표 요약만 남겼다. Claude는 같은 검색에서도 더 풍부한 자료를 읽을 수 있었다.

**둘 다 남은 문제:** 우리 쪽도 답변 전체를 공식 확인처럼 묶었고, Claude도 제3자 검색 발췌를 읽고 공식 확인이라고 표현했다. 맞는 숫자를 쓴 것과 공식 근거를 확인한 것은 다르다.

이전 보고서에서 검색 설명이 중간에 잘려 보인 것은 내가 설명을70자로 잘라 넣었기 때문이다. 이 페이지는 그 표시를 없애고 제목과 링크를 온전히 보여준다. 아래 모델 답변은 실제 출력 그대로다. 답변 자체의 어색한 마무리는 고쳐 쓰지 않았다.

## 비교 조건

같은 Qwen 가중치,64K 문맥,출력4096,temperature0,thinking off로 질문 두 개를 각각 한 번 실행했다. 검색은 실제 웹 결과다. 일반 모드 Claude Code에는 Brave 웹검색 MCP만 허용했고, 우리 쪽에는 기존 검색·본문 읽기·OpenBnB를 유지했다. 두 구성의 도구와 프롬프트가 달라 순수 하네스 효과나 일반적인 승패를 입증한 실험은 아니다.

도구 ID와 실제 MCP 응답, 다음 모델에 전달된 결과를 연결했다. 내부 사고 전체를 본 것은 아니다. 정상 비교의 모든 도구 응답은 다음 모델 호출에 전달됐다.
