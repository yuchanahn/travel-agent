# 004 — 변경 완료 시 커밋·푸시 정책

## 작업한 내용이 코드와 기록에 함께 남도록

### 문제 정의

> **💬 사용자 요청**
>
> 이제부터 매번 뭔가 변경이 있을때마다 커밋 푸쉬 해줘. 가능하지?

구현 결과와 연구 기록, GitHub 반영 상태를 함께 따라갈 수 있어야 했다.

### 문제 분석

파일을 고치는 것, 커밋하는 것, 원격에 푸시하는 것은 다른 상태다. 무엇을 바꾸고 검증했는지 없이 커밋만 쌓이면 나중에 이유를 찾기 어렵다.

### 연구 과정

의미 있는 변경 단위로 검증과 연구 기록을 마친 뒤 관련 파일만 커밋·푸시하는 순서를 정했다. 개인 원문 로그와 무관한 변경은 포함하지 않기로 했다.

### 문제 해결

지속 승인과 작업 절차를 협업 지침에 반영했다. 완료할 때 커밋과 실제 푸시 결과를 함께 알리도록 했다.

### 결과와 남은 문제

이후 메모리 RAG, 코드 해설, Agentic RAG와 문서 변경을 각각 커밋으로 남겼다. 이 단계의 개선은 자연어 답변이 아니라 변경 이유를 찾아갈 수 있는 개발 흐름이다.

## 구현과 실험 상세

날짜: 2026-10-17 (Asia/Seoul).

사용자가 앞으로 변경 작업 완료 시 커밋·푸시를 수행하도록 승인했다. AGENTS.md에 의미 있는 변경 단위의 검증·연구 기록·커밋·푸시 절차를 추가했다. origin은 https://github.com/yuchanahn/travel-agent.git, 현재 브랜치는 main으로 확인했다.

이번 작업의 파일만 명시적으로 스테이징하며 비밀정보·개인 원본 로그·관련 없는 사용자 변경을 제외한다. 강제 푸시와 이력 재작성은 하지 않는다. 푸시 실패 시 로컬 커밋을 보존하고 보고한다. 완료 응답에 실제 커밋과 푸시 상태를 남긴다.
