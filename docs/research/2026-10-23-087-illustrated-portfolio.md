# 087 · 구조·기술·결과가 보이는 항목별 포트폴리오

사용자는 단순히 글을 줄이는 것보다 구조·기술명·도입 의도·성과가 각각 그림1장과 함께 드러나길 원했다. 포트폴리오를 실행 구조, 메모리 RAG, 평가·관측의3항목으로 구성했다. 각 항목에는 기술, 의도·구조, 시도·결과와 코드 토글을 뒀다. 본문 세부 페이지 연결은 추가하지 않았다.

실행 구조와 RAG는 설명용 그림을 생성했고, 평가·관측은085의 실제 비교 화면을 사용했다. 설명용 그림을 실제 앱 화면으로 소개하지 않았다. `scripts/render_portfolio_figures.py`는 Pillow·한국어 글꼴을 사용하며 RAG 검색 수치는082 공개 결과에서 읽는다. 새 모델 호출이나 평가 없이 기존 합성 자료의8/8·MRR0.875·세부 복원0/2→2/2를 설명했다.

생성한 두 그림을 직접 열어 글자·화살표·수치와 배치를 확인했다. Notion 저장 후 이미지3개·토글3개·섹션3개·세부 연결0개와 기존 여행 품질0/2가 유지됨을 확인했다.

UI는 ‘여행 조사 노트’ 컨셉을 제안했다. 사용자 여행 준비 문구를 앞세우고, 접는 노트에 사용자가 고정한 조건·후보를 두며 출처와 확인 상태는 답변 가까이에 둔다. 실행·모델 정보는 접어서 본다. 자동 조건 추출·후보 카드는 추가 구조화와 검증이 필요한 후속 개발이다. 실제 UI 코드 변경은 없다. 상세 제안은 [UI 방향](../portfolio/ui-direction.md)에 보존한다.

새 실험·도구 호출은 없으므로 에이전트 툴콜 로그도 없다. 기존 계약 검사 성적과 여행 품질 결과를 새 측정으로 바꾸지 않는다.
