Notion: [기술명 제목과 시각 구성](https://app.notion.com/p/404d058c022e8140a803cd35a4098271), [선택 근거·공고 매칭·제작 단계](https://app.notion.com/p/404d058c022e81cfb83fe58c17331ee8).

## 요청과 반영

사용자는 기술명을 제목에 넣고 각 기술을 왜 선택했는지 실제 판단 근거를 요구했다. 공고의 요구와 계속 맞춰 보면서 최종 문서까지의 제작 단계를 정하도록 했다.

기존 시각 구성의 파트 제목을 Ollama/Qwen, Codex/Claude Code와 Brave Search MCP, BM25Plus/중복 제거, Tool Calling/MCP, SQLite/BM25 RAG, JSONL Trace/Eval Harness, Human-in-the-loop/JSON으로 바꿨다. 그림과 사진 자리는 유지했다.

상세 제출 본문은 쓰지 않고 기술별 선택 근거를 작성용 문서로 분리했다. 문제·검토한 대안·이유·실제 연구/소스·공고 연결을 묶었다. 기능이 어떤 역할을 하는지와 당시 그 기술을 선택한 이유가 무엇인지는 구분했다. Ollama 복귀, 검색 공급자/API/MCP 전환, 원문 RAG, 검색 선별, 계획서 저장과 사용자 확정 등 기존 기록을 근거로 사용했다.

기술명에 나타난 SQLite·JSON·JSONL 같은 실제 형식에 별도 우월성 비교를 만들어 붙이지 않았다. 확인되지 않은 선택 배경은 내부 확인 항목으로 유지하며 제출 문단의 자발적 해명으로 옮기지 않는다.

## 제작 절차

구조/기술명 → 선택 판단/근거 → 시각 자료 구성 검토 → 공고별 짧은 원고 → 독자 관점 교정 → 요청 시 별도 PDF의 여섯 단계로 계획했다. 각 단계에서 요구사항·주장·그림·근거를 다시 대조한다. 이는 PDF 페이지 수나 매번 승인받는 절차가 아니다.

현재는 구조와 판단 근거 초안을 정리한 단계다. 이미지 자리표시자 교체·원고·사용자 검토·PDF는 남아 있으며 완료로 표시하지 않는다. 제품 코드나 새로운 모델/검색 실험은 없고 실험용 도구 호출 로그도 없다.
