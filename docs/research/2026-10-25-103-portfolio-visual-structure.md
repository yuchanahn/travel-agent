# 103 · 개발 흐름을 구조 다이어그램과 사진으로 먼저 구성

Notion: https://app.notion.com/p/404d058c022e8140a803cd35a4098271

## 요청과 구성

사용자는 상세 내용을 쓰기 전에 개발 흐름과 각 파트에서 보여줄 구조를 정하고, 다이어그램과 기존 사진으로 페이지를 구성하도록 요청했다. 없는 사진은 대괄호로 필요한 장면을 적는다.

공고별 기존 목차는 보존하고 공통 시각 구성 페이지를 만들었다. 제품 소개 → 에이전트 연구 협업과 검색 전략 선택 → 웹 근거 가공 → 실행 하네스 → 메모리 → 실행 추적과 평가 → 편집·확정 가능한 계획서 순서다. 해당 페이지에는 파트 제목·Mermaid 구조도·이미지·사진 자리표시자만 넣었다.

사용자는 서브에이전트와 Claude Code에 검색 방식·원시 데이터 처리를 연구시키고 시간·비용·품질을 검토해 Brave Search MCP를 선택한 과정을 밝혔다. 이를 개발 과정의 협업 구조로 배치했다. 여행 제품 안에서 여러 에이전트가 협업하는 구조로 표현하지 않는다. 구체적인 담당 엔진별 역할은 이 단계에서 임의 배정하지 않았다.

## 기존 자료의 선택

기존 제품 홈·대화·실행 비교·메모리/검색 설명도·실행 구조도·계획서 캡처를 열어 확인했다. 제품 첫 화면, 실행 구조 설명도, 실행 비교, 선택 확정 화면을 연결했다. 실제 화면과 설명도의 캡션을 구분했다.

검색 방식별 조사 장면, 원시 결과/모델 입력 대조, 도구 실행 상세, 메모리 답변 대조, 같은 질문의 개선 비교는 해당 캡처를 확보하지 못해 자리표시자로 남겼다. 기존의 서로 다른 턴 비교 이미지를 동일 질문의 전후 개선 증거로 표시하지 않았다. 저장된 자료로 화면을 재구성하거나 새로운 모델 실험을 수행하지 않았다.

## 확인과 다음 단계

Notion 저장 후 구조도7개·기존 이미지4개와 미확보 장면6개의 자리표시자를 재조회했다. 기존 이미지의 텍스트가 들어 있다는 이유로 별도의 상세 본문을 추가하지 않았다. 현재 페이지는 내용과 이미지 전개의 검토안이며 PDF 지면을 확정한 자료는 아니다.
