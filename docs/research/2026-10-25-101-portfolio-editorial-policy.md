# 101 · 사람이 읽는 포트폴리오와 별도 PDF 제작 규칙

Notion: https://app.notion.com/p/404d058c022e81a684f9fb93f1580554 — 기존100 페이지 상단의 최신 편집 기준101.

## 요청과 반영

사용자는 사람이 읽는 자유양식 PDF를 목표로 짧은 기술 설명과 보기 편한 이미지·다이어그램의 전개를 요구했다. 확장과 사용자 평가를 고려한 실제 설계 판단을 보여주되, 운영 규모 부재나 실패를 스스로 부각하는 해명을 제출 본문에 반복하지 않도록 정했다.

Notion에서 내용과 시각 자료를 먼저 구성한다. 이후 사용자가 PDF 제작을 요청하면 최신 페이지를 읽어 지면·여백·타이포그래피·이미지 배치를 별도로 디자인한다. Notion 기본 내보내기를 최종 제작 방식으로 삼지 않는다.

## 바뀐 작성 기준

설명량보다 독자가 기능·기술·기여를 얼마나 빠르게 이해하는지를 우선한다. 각 파트의 핵심을 먼저 정하고 그 핵심을 보여줄 사진·다이어그램과 기술명을 배치한다. 이미지가 있다는 이유로 모두 싣지 않고 공고별로 순서를 정한다.

기존 공고 분석의 경험 확인 항목은 작성자 내부 자료로 표시했다. 연구 기록은 보존하면서 제출 문구로 자동 옮기지 않도록 했다. 구현과 설계 의도를 구체적으로 설명하고, 사실 확인은 정확한 동사와 필요한 조건에 반영한다. 실제 없는 경력·운영 실적은 만들지 않는다.

실제 적용 문구: “대규모 운영 부재·외부 트래픽 부재·실패를 제출 본문에 자발적인 해명으로 반복하지 않는다.” 루트 지침에서 새 편집 규칙을 읽도록 연결했다.

## 적용 범위

개발 편집 정책을 갱신한 작업이다. 기존 발표 포트폴리오·제품 코드·실험 결과는 수정하지 않았으며 새 포트폴리오나 PDF를 제작한 것은 아니다. 실험용 모델·도구 호출은 없어 실험 로그를 만들지 않았다.

문서 연결·노트 형식 검사를 통과했다. 기존 Notion 분석 페이지 상단에 새 규칙을 넣고 이전 편집 문구와 공고별 내부 확인 절을 수정한 뒤 재조회했다. 문서 검사는 제출 서류의 설득력이나 완성도를 판정하지 않는다.
