# 개발 단계

## 현재 완료

- 로컬 모델 설치와 기본 도구 왕복 테스트
- 프로젝트 배경, 초기 기술 방향, 연구 기록 방식
- Python 패키지 메타데이터와 읽기 전용 상태 조회 CLI
- 미정인 여행 요청의 대표 질문과 검증 사례 10개 설계 (평가 실행 전)
- 대화·도구 원본 저장, 사용자·세션별 메모리 인덱스, BM25/dense/RRF 검색과 근거 기반 답변의 첫 CLI 구현
- 선택적 memory_search/memory_show 도구 루프, 인자·반복·횟수·문맥 제한, 로컬 JSONL 실행 추적과 trace 조회

- 공개 웹검색 도구와 검색 결과 출처·시도/완료 상태 추적, 로컬 모델 통합 실험
- 웹 도구 묶음의 제한된 병렬 실행, 결과 순서·호출 ID 보존과 실패 격리
- 선택형 webserp Google 공급자 연결·오류 분류·DDGS와 동일 검색 질의10개 및 실제 모델 답변 비교 (017, 검색 품질 향상 없음)
- webserp 이슈·프로토콜 재검증과 DuckDuckGo/Yahoo 경로 연결: 세 질의 두 반복에서 공식 도메인6/6, 실제64K 에이전트의 두 주소 답변 확인 (019, Google은 미해결)

## 현재 우선 평가

034부터 사용자 요청에 따라 에이전트 답변 평가보다 [검색 툴 자체의 검증](search-pipeline.md)을 우선한다.042에서 Brave 공급자로 바꿨고043에서 같은 저장 본문의 발췌 경계와 메뉴 의심 신호를 점검했다. 다음은 본문 접근 실패·목적에 맞지 않는 후보·오래된 정보·광고성 글을 구분하는 근거 선택이다. 메뉴 경고는 자동 제외 판정이 아니며 아직 충분한 의미적 품질 검증은 없다. 그 뒤 [여행 검색·본문·답변 기준](travel-search-evaluation.md)에 따라 금액·인용·반복 오류를 확인한다.033 실패를 회귀 사례로 유지한다.

## 다음: 제품과 데이터

우선순위 수정: 사용자는 문맥 압축에서 빠진 대화·조사 근거를 원본에서 복원하는 것을 RAG 도입 이유로 확정했다. [현재 메모리 RAG](memory-rag.md)의 2-Step 경로와 [Agentic RAG](agentic-rag.md)의 선택적 도구 경로를 함께 유지한다. 모든 메모리를 도구로만 제공해야 한다는 원칙은 없다. [006](research/2026-10-17-006-rag-design-review.md)은 초기 고정 문서 코퍼스 검토 이력이다. 아래 대화 흐름 항목은 후속이며 고정 질문 순서를 구현하지 않는다.

- [대표 요청과 기대 행동](research/2026-10-17-005-questions-and-validation.md)에 따라 미정 조건을 다루는 첫 대화 흐름 구현
- 여행지·교통 접근성 데이터의 출처·라이선스·갱신 주기 확인
- 033에서 출처 ID 기반 본문 발췌 도구 구현. 다음은 의미적 근거 확인·요금 조건·추출 누락·실패 회복 검증 (자율 여행 답변 품질은 아직 불합격)
- SearXNG·OpenSERP를 같은 한국어 개발 질의10개로 비교하고 공급자별 실패·지연·관련성을 기록 (013 조사 완료, 실험 전)
- 사용자의 요금·무료 쿼터 회피 선호에 따라 자체 운영을 우선 비교: 메타검색 SearXNG/OpenSERP와 독립 색인 YaCy의 역할·커버리지를 구분 (014 조사, 설치·성능 실험 전)
- Crawl4AI 본문 추출을 동일 URL로 별도 평가하고 기존 검색 요약과 구분 (설치·구현 전)
- 자동 대화·도구 이벤트 저장과 문맥 압축 연결 (현재는 명시적 CLI import/index)
- 주변 원문 읽기·시간 및 정정 관계·근거 패킹 개선
