# 작업 계획과 인수인계

작은 수정은 대화의 짧은 계획과 연구일지로 충분하다. 여러 세션·여러 기능에 걸치는 작업은 이 폴더에 `YYYY-MM-DD-topic.md`로 만든다. 제품의 기존 마무리 범위는 [completion-plan](../portfolio/completion-plan.md)이 기준이며 중복 로드맵을 만들지 않는다.

계획에는 목적·완료 기준·작업 범위·현재 진행·결정 이유·실제 검사 결과·남은 위험·다음 행동을 적는다. 재개에 필요한 명령은 넣되 키·개인 대화·비공개 서버 주소는 넣지 않는다. 시험 데이터를 만들었다면 소유 루트와 정리 상태는 비공개 기록에 보존하고 공개 계획에는 정리 여부만 적는다.

진행 중 파일은 이 폴더 바로 아래에 둔다. 끝나면 `completed/`로 옮기고 링크를 고친다. 검증이 남았으면 완료로 표시하지 않는다. 막힌 작업도 파일을 지우지 않고 이유와 필요한 조건을 적는다. 날짜만 바꾸거나 마지막 답변을 다음 행동 대신 붙이지 않는다.
