# 토스 두 공고의 포트폴리오·자기소개서 제작 단계

상태: 진행 중 — 구조·근거 준비 단계
검토일: 2026-10-25

목표는 사람에게 읽기 쉽고 두 공고의 요구에 각각 답하는 서류다. 기술명·선택 판단·구현·그림이 연결되게 한다. 사용자 검토 없이 작성 에이전트가 최종본으로 확정하지 않는다. 최신 사용자 지시로 두 공고별 실제 포트폴리오 페이지를 작성했다. 추적 화면은 사용자가 제공할 수 있다고 했으며 캡처 연결·검토·PDF 제작은 남아 있다.

## 제작 흐름 · 여섯 단계

| 단계 | 산출물 | 공고 매칭과 다음 단계 기준 | 상태 |
| --- | --- | --- | --- |
| 1. 구조와 기술명 | 공통 개발 흐름·기술명이 있는 제목·도식·이미지 자리 | 각 파트가 실제 구현/개발 경험이며 공고의 어느 요구에 답하는지 연결 | 제목 수정·기존 시각 구성 반영 |
| 2. 선택 판단과 근거 | 기술별 문제·대안·선택 이유·연구/소스 근거 카드 | 공고1의 고객 문제/트레이드오프, 공고2의 구조/미들웨어/운영 판단과 대조. 모르는 선택 이유는 확인 | 작성용 근거 초안 정리 |
| 3. 시각 자료 구성 검토 | 그림별 역할·캡처·placeholder 교체·파트별 배치 | 실제 화면이 주장을 보여주는지 확인. 읽을 수 있는 크기, 시각적 중복, 설명도/실제 화면 구분 | 진행 중, 필요한 장면 미확보 |
| 4. 공고별 짧은 원고 | Notion 포트폴리오 두 버전·자기소개서 초안 각각 | 공고1은 사용자 문제/문맥/행동/개선, 공고2는 구조/추적/메모리/평가/안정성 중심으로 순서와 비중을 조정. 자기소개서 개인 이력·문항은 필요 시 확인 | 포트폴리오 두 초안 작성·추적 캡처 대기, 자기소개서 미작성 |
| 5. 독자 관점 교정 | 제목·기술·판단·그림의 일치와 문장 압축 | 실제 요구를 빠뜨렸는지, 연구 보고서처럼 길어진 곳은 없는지, 자발적 부정 해명·근거 없는 성과는 없는지 점검하고 사용자 검토 반영 | 대기 |
| 6. 요청 시 PDF 디자인·확인 | Notion 최신 내용으로 별도 조판한 자유양식 PDF | 한글 글꼴·이미지 가독성·여백·페이지 나눔·검색 가능한 텍스트·본문/그림 일치 확인, 렌더링 후 육안 검토 | 사용자 PDF 요청 후 진행 |

이 단계 수는 문서 제작 절차이며 PDF 페이지 수가 아니다. 작은 수정마다 새 승인을 요구하는 절차로 쓰지 않는다. 후속 사용자 지시 범위에서 진행하고, PDF는 기존 요청 조건을 지킨다.

## 모든 수정에서 반복할 점검

1. 이 파트는 공고의 어떤 업무에 답하는가?
2. 기술명·내 역할·선택 이유·실제 근거가 같은 이야기를 하는가?
3. 대안을 실제 검토했는가, 아니면 지금 설명을 위해 만든 대안인가?
4. 그림만으로 구조를 따라갈 수 있고 짧은 설명으로 판단을 이해할 수 있는가?
5. 개발 과정의 Codex/Claude Code 협업을 제품의 멀티 에이전트로 혼동시키지 않는가?
6. 이 문장은 실제 구현·의도·결과 중 무엇을 말하는지 정확한가?
