# ADR-0001: 초기 기술 방향

작성: 2026-10-17. 상태: 초기 제안 채택, 실행 핵심은 후속 구현.

## 맥락

실제 여행 계획에서 겪은 불편을 해결하고 GitHub 공개를 준비한다. 현재 Python 3.12와 Docker CLI가 있고 uv는 확인되지 않았다. RTX 3080 Laptop 8GB에서 Ollama 0.40.5와 Qwen3.5 4B Q4_K_M의 기본 실행을 확인했다.

## 결정

1. Python 3.12로 시작한다. 기존 설치를 활용하며 API·검증·평가를 같은 언어에서 구현한다. 초기 환경은 venv와 pyproject.toml로 관리한다. 의존성이 생기면 잠금 파일을 포함한 재현 절차를 도입한다.
2. 구조화된 도구 호출을 사용하는 단일 에이전트부터 구현한다. 모델이 질문·도구 호출·종료를 선택하고, 애플리케이션이 도구 검증·실행·결과 전달·상태 기록을 담당한다.
3. ReAct에서 관찰과 행동을 반복하는 설계 원리를 취하되, 원본 논문의 텍스트 Thought/Action/Observation 파서나 사고 과정 공개를 요구하지 않는다. 초기 모델 테스트는 think=false였으며, thinking 설정의 품질·지연 차이는 후속 실험이다.
4. 최대 모델 호출 단계 6회와 요청 전체 시간 예산 120초를 초기 후보로 둔다. 실제 구현에서는 도구 호출·결과 크기도 제한하고 타임아웃을 전파한다. 수치는 평가 후 조정한다.
5. Ollama는 Windows 호스트에서 실행한다. 지금 Docker로 GPU 실행 환경을 다시 구성하지 않는다. 앱 API와 배포 대상이 정해지면 Dockerfile과 잠금된 의존성을 추가한다. Windows Docker Desktop의 앱에서는 host.docker.internal로 호스트 Ollama에 연결하도록 검증한다. 다른 OS의 네트워크 설정은 별도다.
6. 웹 API가 필요해지면 FastAPI를 우선 검토한다. 현재는 상태 조회 CLI만 구현한다. LangGraph는 체크포인트·재개·복잡한 분기가 필요할 때 검토한다.

## 예상 흐름

사용자 입력 → 누락 조건 확인 → LLM 판단 → 허용 도구와 인자 검증 → 도구 실행 → 관찰 기록 → LLM 재판단 → 근거와 한계가 포함된 답변.

도구 인자에는 타입·범위 검증을 적용한다. 모델이 요청한 도구 이름만으로 임의 코드를 실행하지 않는다. 실제 조회 결과와 fixture를 명확히 구분한다. 확인하지 않은 가격은 확정하지 않는다.

## 트레이드오프

직접 루프를 작성하면 실패·비용·종료 동작을 이해하고 평가하기 쉽지만 세션 관리 등을 구현해야 한다. 프레임워크는 반복 작업을 줄일 수 있어 필요가 확인되면 교체할 수 있도록 모델 호출과 여행 도구를 분리한다. Docker를 미루면 초기 개발은 단순해지지만 배포 재현성 검증은 남는다.

## 공개 전 남은 결정

프로젝트명, 공개 라이선스, 여행 데이터 사용 조건, 사용자 저장 정책, 호스팅과 실제 트래픽 수용 방식. 로컬 8GB 단일 GPU가 사용자 10명의 동시 요청을 처리한다고 가정하지 않는다.
