# 숙소 근거 분리와 추가 본문 읽기 — 069

## 숙소별 근거

`OpenBnB → pack_result → LodgingEvidence.ingest → lodging_evidence → 모델` 경로다.

Airbnb의 HTTPS `/rooms/숫자` URL만 `airbnb:숫자` 키로 식별한다. 표시 이름·검색 지역·좌표로 숙소를 합치지 않는다. 다른 예약 서비스의 숙소와 동일하다고 자동 추정하지 않는다. 검색 후보와 상세 섹션은 원래 MCP 출처 ID별 관측으로 보존하고 요청 날짜·인원도 따로 둔다. 가격 조건 검증은 계속 false다.

`lodging_evidence({})`는 관측한 숙소 키와 출처 목록, `lodging_evidence({"listing_key":"airbnb:111"})`는 해당 숙소의 관측을 반환한다. 모델은 근거를 쓸 수만 있고 임의 시설을 저장할 수 없다. 시설 그룹의 `Not included`를 유지한다. 목록에 없는 시설은 미확인이며 미제공으로 변환하지 않는다. 큰 관측은 통째로 제외하고 `omitted_source_count`와 최대5개 `omitted_source_ids`를 표시한다. 전체 출력은 기본6000바이트다.

현재 사용자·세션의 SQLite 원문 도구 이벤트와 전달된 대화의 도구 메시지에서 복원한다. 웹은 조상 분기만 DB에 넣으므로 다른 대화·형제 분기를 합치지 않는다. 요약으로 과거 도구 메시지가 빠져도 해당 범위의 원문에서 다시 구성할 수 있다. 과거 결과의 패킹은 현재 어댑터로 재구성할 수 있으며, 예전 모델이 정확히 같은 패킷을 읽었다는 뜻은 아니다. 새 근거가 추가되면 같은 키의 재조회가 가능하고, 변화 없는 동일 조회는 기존 중복 방지 정책을 적용한다.

이 기능은 의미적 사실 검증기가 아니다. 웹 블로그에서 여러 숙소를 나열한 문장을 임의로 구조화하지 않으며, 현재 자동 묶기 범위는 OpenBnB다. 모델이 다른 숙소의 정보를 최종 답변에 옮기는 행위까지 프로그램이 차단하지 않는다.

## 동일 문서 추가 읽기

첫 `web_read`는 기존처럼 질문 관련 발췌를 반환한다. 동시에 현재 에이전트 실행에 한정한 캐시에 **추출된 본문**을 저장한다. HTML 전체나 실행된 자바스크립트 DOM을 보존하는 캐시가 아니다. 원본 사이트가 추출 단계에서 제공하지 않은 정보까지 복구하지는 못한다.

잘린 발췌의 `document_token`, `next_start_index=0`을 다음 호출에 넣으면 그 추출문 처음부터 순차적으로 읽는다. 각 결과의 다음 인덱스로 이어가며, 끝에서는 null이다. 인덱스 단위는 유니코드 문자이며 바이트·토큰이 아니다. 순차 모드에서는 query로 재정렬하지 않는다. 질문 관련 발췌의 다음 인덱스0은 발췌 직후 위치가 아니다.

```json
{"source_id":"web:0123456789abcdef","query":"취소 규정"}
```

그 결과가 준 토큰과 위치로:

```json
{"source_id":"web:0123456789abcdef","query":"취소 규정","document_token":"반환된 16자리 토큰","start_index":0}
```

위 토큰 문자열은 자리 표시자다. 실제 호출에는 반환된 16자리 소문자16진수를 사용한다.

같은 실행에서는 검색어를 바꾸거나 순차 구간을 읽어도 동일 추출문을 재사용한다. `cache_hit`, 최초 `fetched_at`과 문서 토큰이 유지된다. `download_bytes`는 최초 문서 다운로드 크기이며 캐시 호출마다 그만큼 다시 다운로드했다는 뜻이 아니다. 캐시는8MiB이며 용량 초과를 오류로 알리고 기존 문서를 몰래 교체하지 않는다. 같은 출처의 병렬 최초 읽기는 한 번 수집하고 서로 다른 출처는 병렬로 수집한다. 새 사용자 턴·새 에이전트 실행에서는 토큰이 유효하지 않으므로 query만으로 먼저 읽는다.

완결 경계를 우선하되, 긴 JSON·공백 없는 문자열은 명시적인 조각으로 나눌 수 있다. 순차 결과는 `text_is_fragment=true`, 경계가 없어 강제로 나눈 구간은 `boundary_split=true`다. 조각 하나를 완결된 사실로 취급하지 않는다. 발췌를 만들 수 없으면 빈 text·이유·순차 읽기 위치를 반환할 수 있다. 메타데이터도 출력 예산을 넘으면 오류다.

추출문 전체는 비공개 trace의 `page_snapshot`에 한 번 남기고 모델에는 선택한 발췌/구간만 보낸다. 캐시 조회도 도구 호출 예산을 사용한다. 새 LLM·검색 공급자·MCP·유료 API는 추가하지 않았다.

## 검증의 범위

숙소 교차 오염·날짜별 관측 분리·사용자/세션 범위·압축 뒤 복원·근거 갱신 후 재조회·한도·문자열 재조립·동시성을 회귀 검사한다. 실제 여기어때 페이지에서1회 HTTP 요청과12구간 순차 읽기로 추출문을 그대로 재조립했다. 합성 근거를 사용한 실제 Nexus 모델의 `lodging_evidence` 왕복도 확인했다. 이는 실시간 요금 검증이나 자유로운 여행3턴 전체의 품질 통과가 아니다. 모델이 인용을 누락한 사례와 공급자429를 연구일지에 그대로 남긴다.
