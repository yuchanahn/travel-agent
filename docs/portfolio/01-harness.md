> 모델이 고르는 행동과 실행기가 보장하는 동작을 분리했습니다.

## 공고에 대한 답

Tool Use·Function Calling·오케스트레이션 요구에 답하는 항목입니다. 단일 에이전트의 도구 루프·MCP 연결·병렬 실행·예산·오류 기록을 설명합니다. 멀티 에이전트 협업을 구현한 경험으로 쓰지는 않습니다.

## 이미 구현한 것

모델이 도구를 요청하면 실행기가 인자를 확인하고 호출한 뒤 결과를 다음 모델 입력으로 전달합니다. 외부 도구는 묶음당 최대3개 병렬 실행하고, 도구 호출 ID와 요청 순서를 유지합니다. 정상 답변·모델 오류·출력 한도·시간 소진을 구분합니다. 같은 요청의 재실행은 차단하지만 모델의 반복 판단까지 해결한 것은 아닙니다.

```mermaid
flowchart LR
 A["모델의 도구 요청"] --> B["인자·허용 도구·예산 확인"]
 B --> C["최대3개 병렬 실행"]
 C --> D["호출 ID별 결과·오류 연결"]
 D --> E["다음 모델 입력"]
```

## 보여줄 문제 해결

076은 검색1회·본문 성공3회 뒤 중복 거절26회로360초에 실패했습니다.077에서 실제 전달문과 상태를 대조해 공백 차이를 부분 읽기로 표시하는 문제를 확인했습니다. 그러나 전체 읽기로 표시된 문서도 재요청했으므로 한 가지 버그를 원인 전체로 단정하지 않았습니다. 최신079는 종료했지만 내용 오류가 남았습니다.

## 경계 검사와 현재 검증 범위

기존 검사에서 병렬 호출 ID·응답 순서·한 도구 오류의 분리와 중복 요청 차단을 확인합니다. 082에서 실행 요약을 추가했고, 083에서 개별 실행 비교를 연결했습니다. 실제 저장 trace 집계와 합성 API/JS 렌더 검사는 통과했습니다. 브라우저 시연은 별도 확인 대상입니다.

합성 모델을 사용한 실행기 검사와 실제 Qwen의 행동 품질을 별도로 발표합니다. 정상 동작하는 기능에 인위적인 실패 장면을 만들지 않습니다.
