> 실사용자가 조건을 바꾸며 대화를 이어갈 수 있는 작은 제품 범위를 완성하려 합니다.

## 공고에 대한 답

소프트웨어 엔지니어링·사용자 경험·신뢰성·설명가능성에 해당합니다. 금융 컴플라이언스나 대규모 사용자 운영을 완료한 경험으로 소개하지 않습니다.

## 이미 구현한 것

조건을 묻고 답하는 웹 채팅, 부모 실행을 잇는 후속 대화, 대화 분기별 원문 저장, 실행 중 삭제 보호와 테스트 세션 삭제가 있습니다. 웹 주소는 로컬50733 하나이며 같은 포트로 재시작합니다. Brave/OpenBnB의 자료와 실패 상태를 표시하며 실제 예약·결제는 하지 않습니다.

## 이번 사용 흐름 — 검증 계획

기존 인수 테스트의 날짜 미정→조건 확정→예산 변경3턴을 재사용합니다. 질문에 맞는 답을 미리 대본으로 강제하지 않습니다.

| 단계 | 기계적으로 확인 | 사람의 근거 검토 |
|---|---|---|
| 첫 조건 입력 | 세션·실행·원문 저장 | 모르는 조건을 임의로 확정하지 않는가 |
| 조건 확정 | 같은 대화로 이어지고 출처 유지 | 후보별 시설·지역·주소가 섞이지 않는가 |
| 예산 변경 | 최신 사용자 발언과 조상 경로 유지 | 최신 예산 반영, 미확인 금액 단정 여부 |
| 종료·삭제 | 테스트 루트 삭제와404 확인 | 실제 사용자 대화를 지우지 않았는가 |

## 추가할 응답 지침 — 아직 적용 전

결론을 먼저 짧게 쓰고 비교에는 표를 사용합니다. 출처는 해당 주장 가까이에 두고, 미확인 항목은 미확인으로 표시합니다. 다른 숙소의 시설·주소·출처를 섞지 않으며, 읽은 문서가 질문에 답하지 않으면 다른 안내나 검색을 선택하도록 안내합니다. native 종료는 유지합니다. 지침만으로 정확도 개선을 보장하지 않으며 같은 질문으로 다시 확인합니다.

## 마무리와 다음 결정

3~5일 동안 확인 가능한 범위만 정리합니다. 검증을 통과하지 못한 부분은 프로토타입의 한계로 남깁니다. 실제 사용자 공유 전에는 대상·접근 방법·기록 보존을 사용자에게 묻습니다. 자동으로 ngrok·외부 배포를 재개하지 않습니다.
