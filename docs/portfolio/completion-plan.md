## 최종 문서 구성

주장은 ‘문제 → 선택 이유 → 실제 코드 → 같은 조건의 검증 → 적용 범위’로 연결한다. 각 페이지는 이미 구현한 기능과 후속 작업이 충돌하지 않도록 한 번만 설명한다. 과거 실험의 원본 질문·답변·접힌 도구 로그는 연구일지에 남긴다.

- [하네스](01-harness.md): 모델의 행동 선택과 실행기의 보장 범위.
- [RAG](02-memory-rag.md): 요약에서 사라진 원문 복원, 검색 방식별 비교와 한계.
- [평가·관측](03-evaluation-observability.md): 실행 완료와 사실 품질을 나누는 기준.
- [제품 흐름](04-product-reliability.md): 후속 대화·최신 정정·세션 삭제·고정 로컬 주소.

```mermaid
flowchart LR
 A["구현과 고정 평가"] --> B["실행 결과·원문 대조"]
 B --> C["기능 성과와 품질 한계 분리"]
 C --> D["실제 화면 확인·캡처"]
 D --> E["문서 반영·읽기 검토"]
```

## 완료 상태와 남은 조건

1. 완료:085에서 실제 브라우저의 합성3턴·지표·비교·시험 대화 삭제를 확인하고 화면7장을 캡처했다. 연결 실패 이력084와 해결 과정을 구분해 보존한다.
2. 095에서 사용자의 전체 검증 요청에 따라 기존 두 질문을 실제 웹으로 실행했다. Brave 검색5회·본문 읽기2회였고 주소·출처 오류가 남아 품질0/2다. 후보 추출 보완은 저장 응답 재생으로 확인했으며 새 실시간 추천 품질로 바꾸지 않는다. 원래 추천3턴의 품질 통과는 여전히 미입증이다.
3. 원래 품질 기준을 통과하지 않으면 프로토타입으로 소개한다. 모델 다운로드·신규 유료 서비스·외부 공유·주제 확장은 자동으로 추가하지 않는다.
