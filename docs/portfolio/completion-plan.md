## 1. 공고를 시험지로 읽는 방법

각 요구사항에 ‘내가 해결한 문제 → 설계 선택 → 실제 코드 → 재현 가능한 검증 → 적용 범위’로 답한다. 모든 키워드를 구현하거나 합격을 보장하는 계획은 아니다. 멀티 에이전트·금융 데이터·대규모 운영 경험이 없는 부분은 공백으로 남기고, 강점이 있는 하네스·메모리·평가·소프트웨어 기본기에 집중한다.

| 공고의 요구 | 지금 보여줄 근거 | 이번에 더할 것 | 완성 시 제시할 자료 |
|---|---|---|---|
| Tool Use·오케스트레이션 | 단일 모델 루프, MCP 발견·허용 도구, 병렬3개, 예산·종료 상태 | 기존 경계 검사를 대표 시나리오로 묶기 | 호출 흐름도·실제 실패/정상 기록 |
| Memory | 원문·요약 분리, 웹 BM25, CLI Dense/RRF/리랭킹 | 고정 메모리 평가와 작은 대조 실험 | 검색 지표·같은 질문의 실제 답변 |
| Eval·trajectory | 고정 여행 질문2개, 실제 입력/출력·도구 ID 연결 | 재현 가능한 평가 요약과 근거 검토표 | 완료율과 사실 품질을 분리한 표 |

| 데이터 정제·파이프라인 | HTML/추출문/목록 분리, 출처·부모·상태, 본문 위치 | 대표 데이터가 어떻게 전달됐는지 사례화 | 입력→정제→모델 전달 구조와 코드 |

## 2. 실행 환경과 범위

- Python 가상환경·Ollama `qwen3.5:4b-q4_K_M`·문맥65536·출력4096·온도0·native 종료 유지. 모델40/도구36/360초도 이번 계획만으로 변경하지 않는다.
- 웹은 기존 `127.0.0.1:50733` 하나다. SQLite·JSONL·기존 웹 UI를 활용하고 새 Docker·벡터DB 서버·유료 관측 SaaS·새 MCP를 추가하지 않는다.
- 외부 검색은 기존 Brave/OpenBnB 연결을 보존한다. 비용 없는 검증은 합성 자료·저장 자료·로컬 모델로 수행한다. 남은 할당량이나 무료 여부를 확인하지 않은 외부 호출은 새로 실행하지 않는다.
- 현재 웹 BM25를 기본으로 평가한다. CLI 하이브리드·리랭킹은 기존 실험을 설명하고, 추가 재현은 로컬 모델 파일이 있을 때만 수행한다. 캐시가 없으면 다운로드·삭제를 자동으로 하지 않고 결정 사항으로 남긴다. 학습 목표인 하이브리드/리랭킹을 구현하지 않은 것으로 지우지 않는다.

## 4. 테스트를 작고 의미 있게 나누기

‘달성하기 쉬움’은 작은 범위의 기능을 검증한다는 뜻이다. 결과를 본 뒤 문항을 빼거나 기준을 낮추지 않는다. 새 쉬운 검사의 통과율로079 여행 질문0/2를 덮지 않는다.

### A. 이미 있는 RAG 설명과 새 고정 평가

007의 기존4문항 결과: BM25 Hit@3=3/4·MRR@3=0.625, Dense=4/4·1.0, Hybrid=4/4·0.875. 리랭킹은 최신 예산1질의의 정정 기록을1위로 올렸다. 이는 기존 소표본 실험이며 최신 회귀 성적이 아니다.057에서는 요약+검색으로 계단87개를 복원했지만 추가 관계 해석이 근거를 벗어나 답변 전체 통과는 아니었다.

새 합성12문항을 제안한다. 근거가 있는8문항은 최신 조건·제외 이유·표현 변형·과거 관측을 묻고, 나머지4문항은 기록 없음2개와 다른 세션/분기2개다. 개발용8개(근거6/음성2)와 최종 확인용4개(근거2/음성2)를 실행 전에 나눈다. 최종 확인용을 보고 수정하면 이후에는 개발용으로 취급한다.

계획상 목표는 정답 근거 포함7/8 이상, 다른 세션/분기2문항의 범위 밖 원문 반환0/2다. 기록 없음2문항은 정답 근거가 없다는 판정과 모델의 미확인 응답을 따로 확인한다. Hit@3와 MRR@3는 근거가 있는8문항에만 계산하며, 범위 격리·무근거 응답을 별도 보고한다. 아직 측정하지 않았다. 현재 BM25 기준을 우선 측정하고 같은 문항으로 가능한 CLI 검색 모드를 비교한다. 검색 순위만으로 최신 정정 적용이 성공했다고 채점하지 않는다.

실제 생성 대조는 최신 예산·제외 이유·기록 없음2개의 대표4문항에 원문 전체/손실 요약만/동일 요약+검색의3조건, 기본12회 Qwen 호출로 제한한다. 요약은 손실을 통제한 합성 입력이라고 명시하고 자연 발생 압축 손실과 구분한다. 최근 대화·질문·모델·시스템 지침은 같게 두고 제공 근거만 바꾼다. 정답 값·근거 연결·불필요한 단정은 사람이 확인한다. 실패/정상 응답과 token·시간을 모두 보존한다.

### B. 하네스·문서 기능 경계

기존 테스트에서①병렬 응답 순서/호출 ID②한 도구 실패와 다른 성공의 분리③반복 네트워크 차단④본문 이어 읽기 재조립⑤형제 세션 격리⑥삭제 중 실행 보호를 대표 묶음으로 선택한다. 새 검사 수를 늘리기 위해 동일한 단위 검사를 복제하지 않는다. 모의 모델·모의 HTTP 검사는 실제 Qwen의 행동 품질과 별도로 표시한다.

### C. 실행 모니터링

새로 만들 것은 모델 내부 사고 감시가 아니라 실행 결과 집계다. 기존 화면의 모델/도구 호출·입출력 token·로그를 재사용한다. 실행별 상태·소요 시간·도구 요청/성공/오류·중복 거절·모델 오류·저장 본문 읽기·자동 HTTP 수집을 따로 보여준다. 누락된 token 값은 미수집이며, 합계 token은 한 번의 문맥 길이나 금액이 아니다.

완료 비율은 정상 종료/전체 실행, 도구 오류 비율은 오류 요청/모든 도구 요청으로 분모를 고정한다. 합성2정상+1실패와 실제079 저장 trace로 집계기를 검증하고 둘을 섞어 제품 성공률로 발표하지 않는다. 작은 표본에 p95나 서비스 SLO를 붙이지 않고 개별 시간과 표본 수를 표시한다. 모델 품질·편향·드리프트를 모니터링했다고 주장하지 않는다.

### D. 여행 답변과 제품 흐름

`examples/live-harness-cases.json`의 두 질문은 그대로 유지한다. 실제 웹을 재조회하는 평가는 기존 제공자 사용이 추가 비용 없이 가능한지 확인된 경우에만 실행한다. 그 결정 전에는 과거079를 기존 성적으로 유지한다. 저장 자료 재생은 별도 오프라인 평가로 표시하고, 수록되지 않은 새 도구 요청은 fixture_miss로 기록하며 실시간 웹으로 자동 대체하지 않는다. 재생 실패를 실사이트 오류로 세지 않는다.

시스템 지침의 제안: 결론부터 간결하게, 비교는 표, 출처는 주장 가까이, 미확인은 명시, 숙소별 시설·주소·출처를 서로 섞지 않기, 읽은 문서에 필요한 근거가 없으면 다른 안내/검색 선택. 이 계획에서 아직 프롬프트를 수정하지 않았다. native 종료와 모델의 행동 선택은 유지한다.

조건 미정→조건 확정→예산 변경3턴은 기존 인수 테스트를 재사용한다. 세션 연결·원문 보존·자기 테스트 루트 삭제는 기계 검사, 최신 조건 반영·시설 혼합·근거 없는 금액 생성은 수동 검사로 분리한다. 실제 사용자 공유는 로컬 검증 후 접근 방법과 기록 보존을 결정해야 하므로 자동으로 ngrok이나 외부 배포를 켜지 않는다.

## 5. 실패→성공을 기록하는 규칙과 중단선

실제 재현된 오류만 ‘실패’로 부르고 수정 후 같은 조건의 통과를 연결한다. 이미 동작하는 기능은 ‘구현→기능 확인’으로 설명한다. 요약만/요약+검색은 비교 조건이며, 일부러 망가뜨린 제품의 전후 성능으로 표현하지 않는다. 작은 샘플의 성공을 일반 성능 향상으로 확대하지 않는다.

새 검증 목표가 미달이면 점수를 바꾸지 않고 실패 이유를 남긴다. P0는 평가와 관측 기반을 완성하는 목표다. 모델 정확도까지 통과하지 못했다면 프로토타입으로 정리하고, 제품 완성이라고 쓰지 않는다. 최종 자료는 공고 요구사항별 네 개의 설명 페이지·실행/평가 표·대표 코드·사진/영상 자리표시자다. 멀티 에이전트·새 검색기·새 예약 API·금융 데이터 전환은 이번 마무리 범위 밖이다.

## 6. 결정과 후속 질문 시점

- 확정:3~5일,로컬 Qwen/Python,추가 비용 없음.
- 추가 임베딩/리랭커 파일이 필요한 경우: 디스크·다운로드 범위를 먼저 확인하고 사용자에게 묻는다.
- 외부 검색이 유료 호출이거나 할당량을 알 수 없는 경우: 네트워크 평가 전에 묻고 자동 진행하지 않는다.
- 소수 사용자 공유 직전: 대상·접근 방법·기록 보존을 묻는다. 신규 비용·외부 공개·모델 교체·주제 변경은 먼저 결정받는다.
