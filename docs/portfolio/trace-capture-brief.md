# 추적 화면 연결 가이드 · 작성용

공고별 실제 페이지의 시각 자료는 답변 두 개의 비교표보다 한 요청 안의 실행·문맥·근거를 보여주는 장면을 우선한다. 아래는 사용자가 제공할 수 있다고 한 캡처의 연결 자리다. 아직 받은 화면이나 제품의 새 구현으로 표시하지 않는다.

| 화면 | 보이면 좋은 정보 | 연결할 파트 |
| --- | --- | --- |
| 호출 스택/실행 경로 | run_agent·execute_batch·도구 실행·반환의 실제 관계. 디버거 스택과 모델 trajectory는 구분 | 토스01, 증권01 |
| Agent trajectory | 한 실행의 시간순 모델·도구 호출, 호출 ID, 선택 단계의 인자/결과, 다음 모델 입력 | 토스05, 증권02 |
| Context 추적 | 최근 대화·요약·검색 원문·출처 ID가 실제 요청에 들어가는 흐름 | 토스02, 증권03 |
| 원시 결과→모델 입력 | 같은 출처의 검색 원문·선별된 발췌·실제 전달 내용 | 토스04, 증권04 |
| 평가 검토 | 동일 질문·기준 근거·사용 문맥·답변의 연결 | 증권05, 토스05 |
| 개발 에이전트 협업 | 조사 과제 분담·각 결과·선택 검토 | 토스03 |
| 상태 복원 | 같은 대화·계획서의 저장과 재시작 복원 | 증권06 |

한 화면에 원본 JSON 전체를 축소해 넣기보다 필요한 호출과 문맥 영역이 읽히도록 선택한다. 문서 배치용 주석은 실제 ID·시점을 바꾸지 않는다. 같은 장면을 두 공고에 사용할 수 있어도 앞세울 영역과 설명은 공고의 주장에 맞게 고른다.

수신 후에는 해당 파트 주장과 실제 화면을 대조하고 개인정보·비밀정보를 확인해 교체한다. 제공받은 이미지가 없으므로 이번에는 실험을 다시 실행하거나 비교 화면을 추적 화면인 것처럼 사용하지 않았다.
