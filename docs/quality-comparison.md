# 개선 전후 품질 비교 — 070

사용자가 요청한 실제 검색 도구 활용 비교는 [073 연구일지](research/2026-10-20-073-live-harness-comparison.md)를 따른다. `compare_live_harnesses.py`는 기존 여행 도구와 Claude Code에 등록된 실제 Brave MCP만을 사용한다. `summarize_live_harnesses.py`는 모델 도구 ID·MCP RPC ID·다음 모델 tool_result를 연결한다. 합성 결과를 주입하지 않으며 실제 검색·반환 자료·최종 답변을 보존한다. 이는 서로 다른 실제 구성의 비교이고, 도구·locale·프롬프트 차이를 제거한 순수 하네스 인과 실험은 아니다. 072는 합성 도구 예비 실험으로 범위를 정정했다.

[072 연구일지](research/2026-10-19-072-qwen-harness-comparison.md)는 과거 합성 도구 예비 비교다. `scripts/compare_harnesses.py`와 `research/072-harness-results.json`은 그 재현·결과 확인용으로 보존한다. 실제 웹검색 비교를 대체하지 않으며, 070의 버전 전후 평가나 073 결과와 합산하지 않는다.

## 평가할 질문

069에서 추가한 숙소 근거 재조회·본문 추가 읽기·시스템 지침이 **동일한 근거에 대한 최종 답변의 정확성**을 개선하는지 확인한다. 검색 공급자의 품질이나 실제 예약 가격을 평가하는 실험은 아니다.

비교 대상은 개선 전5e9c79c와 개선 후8945ebf의 **전체 src/travel_agent 스냅샷**이다. 이전 프롬프트만 현재 실행기에 넣는 방식과 구분한다. 새로운 코드 수정으로 평가 도중 제품 행동을 고치지 않는다.

## 사전에 정한 절차

- 공개 합성4사례를 각각3회·2버전, 총24회 실행한다. 사례별8개 이진 기준으로 최대96점/버전이다.
- 두 버전에 같은 사용자 질문·같은 초기 도구 메시지·같은 범위의 원문 메모리·같은 HTML을 제공한다. 실제 모델의 도구 선택과 생성 답변은 고정하지 않는다.
- 이번070 실행은 당시 Nexus 공급자를 사용했다. 요청 모델·실제 응답 모델·온도·토큰·도구 호출·오류는 비공개 trace에 남긴다. 온도0·출력4096·모델8회·도구8회·120초로 동일하게 제한한다.
- 실행 순서는 사례·반복별로 이전→현재와 현재→이전을 교대한다. 이12쌍에서6쌍씩 두 순서를 사용한다.
- 호출 전에 질문·자료·평가 기준·버전·전체 실행 순서를 비공개 protocol.json으로 보존한다.
- 웹 검색·본문 수집·MCP 결과는 고정 자료로 대체한다. 외부 웹 요청이나 예약·결제는 하지 않는다. 원본 스냅샷의 본문 추출·발췌·근거 조회·메모리·하네스 로직은 그대로 사용한다.
- 새 MCP 검색·상세 도구는 양쪽 모두 노출하지 않는다. 이전 MCP 결과 형식의 고정 입력과 원문 메모리만 제공한다. 따라서 실제 서비스에서 이전 버전이 MCP를 다시 호출해 확인하는 대안까지 비교한 것은 아니다. 이번 범위는 주어진 근거의 해석·복원이다.
- 완료된 쌍만 사실 점수에 넣고, 모델 오류·시간/호출 한도 등은 별도 실패율로 표시한다. 한쪽 실패를 사실 정확도0점으로 섞지 않는다. 제외한 분모도 명시한다.
- 자동 LLM 심판이나 단순 키워드 일치로 사실을 판정하지 않는다. 미리 정한 기준을 실제 답변·전달 근거·도구 로그와 대조하여 수동으로0/1점을 부여하고 각 판정 이유를 남긴다. 표와 결론이 충돌하거나 모호하면 해당 기준은 실패다.
- 채점자는 구현을 수행한 동일 에이전트이며 독립·블라인드 평가가 아니다. 사전 기준과 공개 답변으로 판단을 재검토할 수 있게 한다.

## 실행과 검토

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_quality.py --output data/private/quality-new
```

새 비공개 폴더를 지정한다. 질문/정답 기준은 examples/quality-cases.json, 평가 집계는 src/travel_agent/quality.py의 paired_summary다. 공급자429가 발생하면 자동 재시도·공급자 변경 없이 남은 일정을 멈추고 보고한다. 그 상태에서 전체 평가를 마쳤다고 표현하지 않는다.

070의 첫3회 중1회가429여서 최초 일정을 멈췄다. 진단상 일부 상위 공급자의 무료 사용량·월 한도였고 동일 게이트웨이의 다른 경로는 응답했다. 이후 질문·근거·버전·점수 기준을 바꾸지 않고, 실패한 슬롯은 재실행하지 않으며 **미실행 슬롯만 계속하는 절차**를 사전에 추가했다. `--resume --continue-after-provider-errors --interval 15`로 재개하며, 전송 응답의 X-Routed-Via 등 허용한 헤더만 추가 기록한다. 서비스 설정·키·공급자 우선순위는 바꾸지 않는다. 최초 protocol.json과 추가 절차는 따로 남긴다.

같은 요청 모델명만으로 동일 상위 공급자라고 단정하지 않는다. `paired_summary(report, require_route_match=True)`는 양쪽이 완료됐고 실제 성공 응답 경로가 단일·동일하게 관찰된 쌍만 점수에 포함한다. 초기 경로 헤더 미수집 쌍과 경로가 다른 쌍은 별도 제외한다. 게이트웨이 자체의 숨은 재시도·캐시·추론 조건까지 독립적으로 통제한 실험은 아니다.

각 worker는 임시 SQLite 메모리를 닫고 삭제한다. 웹 UI의 대화를 생성하지 않으므로 사용자 대화나 기존 서비스는 건드리지 않는다. 스냅샷·답변·실행 로그는 비공개 평가 폴더에 남긴다. 재실행도 모델 호출 비용/사용량을 사용한다. 입력·출력 토큰 수는 보고할 수 있지만 공급자 과금액을 측정하지 않고 금액 절감을 주장하지 않는다.

071에서 사용자가 웹 공급자를 Ollama로 복귀시켰다. 현재 비공개 설정을 사용하는 새 실행은 Ollama를 사용할 수 있으므로 공급자·모델을 확인하고 다른 결과 폴더에 기록한다. Nexus의070 결과와 섞지 않는다.

## 결론의 범위

평가 결과는 이4종 합성 사례와 동일 모델 설정에서의 전후 비교다.3회 반복을 독립적인 실제 사용자3명처럼 해석하지 않는다. 유의성이나 일반 여행 품질 향상을 주장하지 않으며, 같은 근거를 더 정확히 사용하는지와 어떤 실패가 반복되는지 보고한다. 실제 여행3턴 완료·검색 후보 품질·실시간 요금·재고·웹 접근 안정성은 별도 검증이 필요하다.
