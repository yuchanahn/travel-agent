## 현재 운영 방식 — 067

주소는 **http://127.0.0.1:50733/** 하나로 고정한다. 공유용 ngrok과 Docker 웹2개는 중지했고 컨테이너 자동 재시작도 해제했다. 현재는 호스트 웹 하나만 운영한다. Nexus·Ollama 공급자와 기존 대화·Docker 볼륨은 유지한다. 아래066 이전의 다른 포트·Docker 시작 안내는 과거 이력이다.

```powershell
.\scripts\start_web.ps1                # 이미 실행 중이면 그대로 사용
.\scripts\restart_web.ps1              # 같은 주소로 종료 후 재시작
.\scripts\start_web.ps1 -Action stop    # 이 프로젝트의 호스트 웹 중지
```

스크립트는 백그라운드로 실행하고 건강 응답을 확인한다. 시작을 반복해도 서버를 추가하지 않는다. 작업 공간의 venv 실행 파일과 자식 프로세스 관계로 소유권을 확인하며, 단순히 python이라는 이름으로 종료하지 않는다. 재시작은 실행 중 요청을 중단할 수 있다. 데이터 폴더는 삭제하지 않는다. 포트를 다른 프로그램이 사용하면 오류로 중단하고 다른 포트로 넘어가지 않는다. 동시에 시작·재시작 명령을 실행하면 작업 공간별 mutex로 직렬화한다.

LLM 공급자는 비공개 llm-config.json 설정을 계속 사용한다. 실행 기록과 로그는 data/private/web-host, 관리 스크립트의 stdout·stderr·launcher PID는 data/private/web-runtime에 둔다. Docker 경로는 수동 실험을 위한 과거 구성으로 남겨두지만 기본 start_web.ps1은 Docker를 띄우지 않는다.

## 실행

058에서 ngrok 공유용 인스턴스를 별도로 띄웠다. 기존 로컬 기록과 다른 컨테이너·볼륨을 사용하며 HTTPS Basic Auth로 보호한다. WEB_PUBLIC_ORIGIN_FILE에 적힌 정확한HTTPS Origin만 추가 허용하며 Host rewrite 뒤에도 로컬Host 검사를 유지한다. 인증정보와 현재 주소는 Git 제외data/private/share/access.json에 있다. 공유 계정 접속자는 공유 공간의 대화 목록을 함께 보며 개별 사용자 인증은 아니다. 중지는 scripts/stop_share.ps1이다. 자세한 검증은 [058](research/2026-10-19-058-ngrok-share.md)을 따른다.

호스트 Ollama가 실행 중이어야 한다. Brave 키 한 줄은 Git 제외 파일 data/private/brave-api-key에 둔다. 기존 로컬 키를 그대로 사용하며 Docker에는 읽기 전용 secret으로 전달한다.

```powershell
.\scripts\start_web.ps1
```

스크립트는 Docker를 빌드·백그라운드 실행하고 준비 상태를 기다린 다음 접속 주소를 출력한다. 포트는127.0.0.1에만 공개하고 Docker가 빈 호스트 포트를 배정한다. 새로 생성하면 포트가 바뀔 수 있으므로 아래 명령으로 현재 값을 확인한다.

```powershell
docker compose port web 8000
docker compose ps
docker compose logs --tail 30 web
# 중지하면서 실행 기록 볼륨은 보존
docker compose down
```

Ollama는 host.docker.internal:11434로 연결하고 컨테이너 시간대는Asia/Seoul이다. 기본 모델은qwen3.5:4b-q4_K_M, 컨텍스트65536, 출력 상한4096이다(056). Compose의 환경 변수로 모델·컨텍스트·출력 상한을 바꾼 뒤 다시 실행할 수 있다. 모델 다운로드나 Ollama 설정 변경은 수행하지 않는다.

## 화면에서 확인하는 것

- 모델 호출·검색·읽기 진행 상태 및 실제 인자·반환 결과를 펼쳐 보는 실행 기록.

- 최근 실행 다시 보기와 새로고침 복원. 완료된 실행의 경과 시간은 종료 시각으로 고정한다.

## 실행 구조와 기록

모델 호출 기본 한도는 최종 정리를 포함해12회다. 도구 호출8회·요청180초 한도는 그대로다. 다음 행동 재요청도 모델 호출 횟수에 포함한다.

Python 표준 ThreadingHTTPServer가 정적 화면과 로컬 JSON API를 제공한다. POST /api/runs로 요청을 넣고 GET /api/runs/실행ID를 폴링해 실제 trace의 관찰 가능한 이벤트를 받는다. 모델의 숨은 thinking과 전체 시스템 입력은 화면 API에 노출하지 않는다. 생성 응답은 모델 호출이 끝난 뒤 표시하며 토큰 단위 스트리밍은 아직 없다.

한 번에 모델 요청1개를 실행하고 최대3개(실행1·대기2)를 받는다. 초과하면429로 알린다. 사용자·세션·DB 경로·Ollama 주소는 모델이나 브라우저 요청 인자로 바꿀 수 없다. 요청마다 부모 경로의 원본만 담은 메모리 DB를 만들어 다른 대화·분기와 분리한다. 이어지는 대화는 서버에 저장된 부모 실행의 실제 메시지를 읽어 전달한다. 브라우저가 임의의 모델 메시지나 출처를 주입하지 않는다. 웹 이미지는 BM25 색인을 사용하며 임베딩·torch 모델을 설치하지 않는다. 기존 호스트의 전체 Python 개발 환경은 그대로 사용한다.

057부터 이전 대화와 요약의 직렬화 크기가32000 UTF-8바이트를 넘으면 최근 사용자 턴2개를 남기고 더 오래된 부분을 Ollama로 요약한다. WEB_CONTEXT_COMPACT_BYTES(4000~128000)·WEB_CONTEXT_KEEP_TURNS(1~10)로 조정한다. 바이트 기준이지 정확한 모델 토큰 수가 아니다. 요약은 추가 모델 호출이며 최대30초, 에이전트 실행은 기존180초로 별도다. 실패·빈 출력·length·8000바이트 초과·크기 감소 없음이면 기존 문맥과 이전 요약을 유지한다. 최근 턴만으로 큰 경우 요약을 건너뛰고 기존 입력 한도196608바이트를 적용한다. 정상 완료된 답변에서만 이어갈 수 있고 대화 연결은 최대100턴이다. WEB_UI_PORT를 지정하면 재생성 때도 같은 포트를 사용한다.

원본 사용자 발언·관찰 가능한 모델 답변·도구 결과 및 인자/호출ID는 덮어쓰지 않고 각 실행의 비공개SQLite와trace에 저장한다. 원본에서300자 창·40자 겹침의 한국어 단어/bigram BM25 인덱스를 자동 생성한다. 창의 문자 위치를 보존하며 임베딩·형태소 모델 다운로드는 하지 않는다. 기존 호스트CLI의Kiwi/E5 하이브리드·리랭킹과 별도 경로다.

요약이 있는 대화는 현재 질문으로 과거 원문을 먼저 검색해 최대3개·6000바이트의 결과를 답변 입력에 넣는다(2-Step). 이후 모델이 memory_search·memory_show를 선택하는 경로도 열어 둔다. 자동 검색은 모델 툴콜 횟수에 포함하지 않고 memory_recalled 이벤트로 표시한다. 요약 호출 수·토큰·시간과 자동 검색 결과, 저장 원본 수를 실행 과정에서 확인할 수 있다. 모델 호출·입출력 합계는 에이전트 루프 기준이며 요약 호출 사용량은 별도다.

새 질문의 DB에는 서버가 선택한 부모 경로의 과거 원본만 넣는다. 같은 부모에서 갈라진 다른 분기나 새 대화의 기록은 포함하지 않는다. 서버가 루트 세션을 지정하며 모델·브라우저는 사용자/세션/DB 경로를 전달하지 못한다. 기존 실행은 이어서 질문할 때 그 부모 경로의 기록을 가져온다. 서버 재시작 뒤에는 비공개context.json의 요약·최근 문맥을 복원한다. 요약과 검색은 사실 검증이 아니며 최신 정정과 원문 역할·시점 확인이 필요하다. 로그인·다중 사용자 권한 검증은 아직 없다.

질문·결과·실행 trace는 Docker named volume web_runs에 보존한다. 최근30개는 다시 볼 수 있고 더 오래된 원본 파일은 자동 삭제하지 않는다. 재시작 시 진행 중이던 요청은 중단됨으로 표시하며 다시 실행하지 않는다. 사용자 질문을 노션이나 Git에 자동 업로드하지 않는다. 공개 연구일지에는 별도로 실행한 비민감 테스트만 기록한다.

.dockerignore는 소스와 런타임 의존성 파일만 허용해 키·개인 원본·Git 이력이 이미지 빌드 문맥에 들어가지 않도록 한다. 컨테이너는 UID10001로 실행한다. 호스트 포트를 로컬에 바인딩하고 Host·Origin 검사와 JSON 요청 검증을 적용한다. 인터넷 공개·계정 로그인·여러 사용자 권한 분리는 이번 범위에 포함하지 않았다.

실제 브라우저 입력·답변·Brave 호출·새로고침·모바일 확인 결과는 [045 연구일지](research/2026-10-19-045-local-web-interface.md)를 참고한다.
