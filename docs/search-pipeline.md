# 검색 툴 자체의 수집·재정렬·발췌

034부터 에이전트 답변 평가를 보류하고 검색 도구 자체를 검증한다. 새 경로는 독립 CLI다. 기존 에이전트의 `web_search`를 아직 대체하지 않는다.

현재 실행 순서는 **검색 결과 먼저 수집·임시 보관 → 제목·요약 후보의 중복 묶기·BM25Plus 재정렬 → top_k 선택 → 선택 URL의 본문 수집 → 예산 안의 관련 문단 선택 → 출처별 Markdown 발췌 패킷**이다. 모든 후보 사이트의 본문을 먼저 내려받는 것은 아니다. 수집 루프가 끝난 뒤 후처리하며, 모델용 패킷은 digest이고 현재 CLI stdout으로만 확인한다. Python 반환 보고서는 디버깅용 전체 자료도 포함한다. 임베딩 검색·LLM 문장 생성 요약·출처 간 사실 합성은 미구현이다.

```powershell
python -m travel_agent web research "국립춘천박물관 관람시간 휴관일 교통"
python -m travel_agent web research "국립춘천박물관 관람시간 휴관일 교통" --pages 3 --top-k 5 --read-pages 5 --max-bytes 6000 --keep-dir data/private/search-pipeline/manual
python scripts/evaluate_search_pipeline.py
```

1. 원래 검색어로 Bing HTML을 받고 임시 디렉터리에 저장한다. top_k를 먼저 적용하지 않는다.
2. 응답의 다음 페이지 링크에서 같은 q와 Bing `/search` 경로를 확인하고 first·FORM·FPIG만 이어받는다. 기본 최대3페이지·설정 최대10페이지다. 다음 링크가 없거나 새 URL이 없는 반복 페이지, 오류이면 중단한다. 지정한 수의 결과나 전체 웹 검색을 보장하지 않는다.
3. 전체 후보의 제목·URL·요약과 페이지·순위를 저장한다. 추적용 URL 인자를 제거하고 같은 URL을 묶는다. 충분히 긴 제목·요약의 문자 유사도0.92 이상도 같은 묶음으로 처리하되 원래 출처들을 보존한다. 같은 주제 전체를 합치는 의미 군집화는 아니다.
4. 단어와 한국어 문자 bigram을 사용한 BM25Plus로 제목(2배)·요약을 재정렬한다. 겹치는 쿼리 토큰 비율0.25 미만을 기본 제외한다. 이는 개발용 휴리스틱이며 관련성 확률·의미 평가가 아니다. 동의어·다국어 처리와 핵심 개체 구분은 미완성이다. 같은 호스트 최대2개, 최종 후보 기본5개·최대10개다.
5. 선택한 기본5개 URL의 본문을 최대3개 worker로 읽는다. 기존 공개 주소 검증·IP 고정 연결·TLS 검증을 사용한다. 리다이렉트는 따르지 않는다. 최대2MiB HTML을 로컬에서 Markdown으로 추출하고 인접 문단을 최대600자로 묶어 BM25로 최대3개·합계1000자 이내의 발췌를 고른다.035부터 최종 출처별 바이트 예산을 먼저 계산하고 전체 추출본에서 다시 문단을 선택한다. 예산에 맞춰 문단 크기를 줄이며 뒤의 중요 문장을 앞부분 자르기로 버리지 않도록 한다. 페이지마다 원문과 추출본을 저장한다.
6. 제목·URL·출처 ID·본문 발췌 또는 검색 요약을 기본6000 UTF-8 바이트 이내로 출력한다. URL은 자르지 않고 각 출처의 예산을 나눈다. 전문 전체를 모델에 넣지 않는다. 문장 생성 요약이나 여러 출처의 사실 통합은 하지 않는다. 서로 다른 출처의 내용은 구분한다.

기본 임시 파일은 실행 종료 때 지운다. `--keep-dir`를 지정하면 요청 ID별로 보존하며 직접 정리할 때까지 남는다. 개발 실험은 Git에서 제외되는 `data/private/` 아래만 사용한다. 캐시 재사용·자동 장기 색인은 없다.

`report.json`에는 원래 후보 전체, 묶음·점수·토큰 겹침, 검색·본문 HTTP 이벤트와 오류, 실제 전달할 digest를 남긴다. 새 CLI의 stdout은 digest만 표시한다. `page_fetched=true`는 본문 다운로드 성공이고, `content_kind=page_excerpt`여야 본문 발췌가 전달된 것이다. 다운로드 후 추출이 실패하면 true이면서 search_snippet일 수 있다. 둘 다 최신성 검증을 뜻하지 않는다.

`retrieval_complete=false`는 전체 검색 공간을 다 받았다는 보장이 없다는 뜻이다. `no_next_link`도 전체 검색 결과의 소진으로 해석하지 않는다. `evidence_status=insufficient_candidates`는 현재 후보가 설정한 문자 겹침 기준을 통과하지 못했다는 뜻이며 웹에 정보가 없다는 뜻이 아니다.

## 품질 판정

- 수집: 실제 카드 수, 고유 URL 수, 반복·오류·중단 이유, 목표 자료가 후보에 있는지.
- 재정렬: 같은 저장 응답의 원래 top3와 재정렬 결과를 비교한다. 새 조회 간 차이를 재정렬 효과로 계산하지 않는다.
- 근거: 선택 자료가 질문의 핵심 개체와 조건에 맞는지 직접 판정한다. BM25·URL 개수·토큰 겹침만으로 통과시키지 않는다.
- 발췌: 원문에서 필요한 문장·숫자·조건·예외가 유지되는지 비교한다. 발췌 길이가 짧다는 것만으로 품질·토큰 절감을 주장하지 않는다.
- 표현: 출처 ID·URL·본문/검색 요약 구분을 유지하고 실제 UTF-8 바이트 한도를 검사한다.
- 내장 검색 비교: 같은 검색어로 관찰된 URL·핵심 정보의 확보 여부를 비교한다. 내장 검색은 정답 목록 전체가 아니고 검색엔진·색인·쿼리 변환·재정렬 내부를 통제하지 못한다. 같은 Bing 결과라고 가정하지 않는다.

034의 공개3질의는 일반 품질 통과가 아니다. 춘천·Python은 반복 조회에서도 후보 부족이 남았고, 강릉도 조건 충족·본문 발췌 품질이 미검증이다. 현재 파이프라인의 기계적 검사와 목표 검색 품질은 구분한다. 연구일지034를 참고한다.

035에서는 같은 코드의 반복 조회에서 춘천·Python 공식 자료를 확보했지만 요청 옵션이 해결 원인이라고 확인하지 못했다. count=50도 카드10개였으며 일부 변형은 무관한 결과·파싱 실패였다. 기본 요청 옵션은 유지한다. 동일한 저장 본문으로 재구성한 출력은 기본6000바이트 안에 들어갔고 Python 공식 문서의 ExceptionGroup 표식을 복원했지만, 강릉 조건의 근거는 여전히 부족했다. 바이트 감소를 측정된 토큰·비용 절감으로 표현하지 않는다.

```powershell
python scripts/probe_bing_query_quality.py
python scripts/repack_search_evidence.py data/private/search-pipeline/035-repeat
```

첫 명령은12회 직접 검색을 실행하는 별도 조사다. 두 번째 명령은 기존 evaluate_search_pipeline.py 실행 폴더의 summary.json과 저장된 추출본이 있어야 하며 네트워크·LLM을 호출하지 않는다. 질의·제목 헤더를 제외한 실제 전달 본문에서 표식 유무를 비교한다. 표식 검사는 의미적 품질 평가가 아니다.

## 036: 언어·지역과 응답 형식 조사

같은 q라도 지역·언어·세션 등 요청 맥락이 다르면 같은 입력이 아니다.036의42회 순서 섞은 반복 조사에서는 Python 질의의 `mkt=en-US`와 `cc=us`가 각각3회 모두 목표 문서를 놓치고 무관한 결과를 반환했다. q만 전송·setlang=en·세션 재사용은 각3회 목표를 확보했다. 과거의 q만 보낸 실패까지 같은 원인으로 설명한 것은 아니다. 응답200·검색창에 정확한 q가 남아 있다는 사실만으로 검색 성공을 판정하지 않는다.

언어·지역을 명시하려면 연구 CLI의 `--locale ko-KR` 또는 `--locale en`을 사용한다. 기본 none은 기존 요청을 유지한다. 웹검색에 mkt를 보내지 않고 setlang을 사용하며 cc=US/CN/RU는 보내지 않는다. US는 로컬에서 실패를 재현했고 CN/RU 제외는 외부 수정안에 따른 예방적 설정으로 직접 검증하지 않았다. 이 설정의 일반 품질 우위는 확인하지 않았다.

```powershell
python -m travel_agent web research "국립춘천박물관 관람시간 휴관일 교통" --locale ko-KR
python -m travel_agent web research "국립춘천박물관 관람시간 휴관일 교통" --serp-format rss --keep-dir data/private/search-pipeline/rss
python scripts/diagnose_bing_variance.py
python scripts/diagnose_bing_variance.py --rss-only
```

RSS는 같은 Bing `/search`에 format=rss를 명시하는 별도 응답 경로다. 기본 HTML을 자동 대체하거나 실패 뒤 몰래 호출하지 않는다. XML 외부 엔티티·DTD를 허용하지 않고 제목·URL·요약을 기존 재정렬·본문 읽기·발췌 경로로 넘긴다. 기본 에이전트 web_search는 그대로다.

RSS 조사4질의×3회에서 모두 목표 주소를 확보하고 질의별 URL 순서가 같았다. 이 시간대·한 호스트의 관찰이며 장기 안정성·의미적 정확성 검증은 아니다. 실제 반환은 각10개였고 페이지·날짜·언어·SafeSearch 필터의 동일 동작을 보장하지 않는다. `--pages`가 커도 RSS는 한 피드에서 멈추고 `stop_reason=feed_limit`, `retrieval_complete=false`로 기록한다. 본문 실험에는 여전히 무관한 후보와 미흡한 발췌가 남았다.

진단 스크립트는 기본42회, --rss-only는12회 직접 검색한다. 원문은 비공개에 보존하고, 세션·쿠키는 값 대신 정책·이름만 기록한다. 숫자 HTTP 버전3은 curl enum의V2_0(HTTP/2)이며 HTTP/3이 아니다. 상세 원인 후보·반복 결과·확정 범위는 연구일지036을 따른다.
