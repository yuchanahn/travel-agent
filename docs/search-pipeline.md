# 검색 툴 자체의 수집·재정렬·발췌

034부터 에이전트 답변 평가를 보류하고 검색 도구 자체를 검증한다. 새 경로는 독립 CLI다. 기존 에이전트의 `web_search`를 아직 대체하지 않는다.

```powershell
python -m travel_agent web research "국립춘천박물관 관람시간 휴관일 교통"
python -m travel_agent web research "국립춘천박물관 관람시간 휴관일 교통" --pages 3 --top-k 5 --read-pages 5 --max-bytes 6000 --keep-dir data/private/search-pipeline/manual
python scripts/evaluate_search_pipeline.py
```

1. 원래 검색어로 Bing HTML을 받고 임시 디렉터리에 저장한다. top_k를 먼저 적용하지 않는다.
2. 응답의 다음 페이지 링크에서 같은 q와 Bing `/search` 경로를 확인하고 first·FORM·FPIG만 이어받는다. 기본 최대3페이지·설정 최대10페이지다. 다음 링크가 없거나 새 URL이 없는 반복 페이지, 오류이면 중단한다. 지정한 수의 결과나 전체 웹 검색을 보장하지 않는다.
3. 전체 후보의 제목·URL·요약과 페이지·순위를 저장한다. 추적용 URL 인자를 제거하고 같은 URL을 묶는다. 충분히 긴 제목·요약의 문자 유사도0.92 이상도 같은 묶음으로 처리하되 원래 출처들을 보존한다. 같은 주제 전체를 합치는 의미 군집화는 아니다.
4. 단어와 한국어 문자 bigram을 사용한 BM25Plus로 제목(2배)·요약을 재정렬한다. 겹치는 쿼리 토큰 비율0.25 미만을 기본 제외한다. 이는 개발용 휴리스틱이며 관련성 확률·의미 평가가 아니다. 동의어·다국어 처리와 핵심 개체 구분은 미완성이다. 같은 호스트 최대2개, 최종 후보 기본5개·최대10개다.
5. 선택한 기본5개 URL의 본문을 최대3개 worker로 읽는다. 기존 공개 주소 검증·IP 고정 연결·TLS 검증을 사용한다. 리다이렉트는 따르지 않는다. 최대2MiB HTML을 로컬에서 Markdown으로 추출하고 인접 문단을 최대600자로 묶어 BM25로 최대3개·합계1000자 이내의 발췌를 고른다. 페이지마다 원문과 추출본을 저장한다.
6. 제목·URL·출처 ID·본문 발췌 또는 검색 요약을 기본6000 UTF-8 바이트 이내로 출력한다. URL은 자르지 않고 각 출처의 예산을 나눈다. 전문 전체를 모델에 넣지 않는다. 문장 생성 요약이나 여러 출처의 사실 통합은 하지 않는다. 서로 다른 출처의 내용은 구분한다.

기본 임시 파일은 실행 종료 때 지운다. `--keep-dir`를 지정하면 요청 ID별로 보존하며 직접 정리할 때까지 남는다. 개발 실험은 Git에서 제외되는 `data/private/` 아래만 사용한다. 캐시 재사용·자동 장기 색인은 없다.

`report.json`에는 원래 후보 전체, 묶음·점수·토큰 겹침, 검색·본문 HTTP 이벤트와 오류, 실제 전달할 digest를 남긴다. 새 CLI의 stdout은 digest만 표시한다. `page_fetched=true`는 본문 다운로드 성공이고, `content_kind=page_excerpt`여야 본문 발췌가 전달된 것이다. 다운로드 후 추출이 실패하면 true이면서 search_snippet일 수 있다. 둘 다 최신성 검증을 뜻하지 않는다.

`retrieval_complete=false`는 전체 검색 공간을 다 받았다는 보장이 없다는 뜻이다. `no_next_link`도 전체 검색 결과의 소진으로 해석하지 않는다. `evidence_status=insufficient_candidates`는 현재 후보가 설정한 문자 겹침 기준을 통과하지 못했다는 뜻이며 웹에 정보가 없다는 뜻이 아니다.

## 품질 판정

- 수집: 실제 카드 수, 고유 URL 수, 반복·오류·중단 이유, 목표 자료가 후보에 있는지.
- 재정렬: 같은 저장 응답의 원래 top3와 재정렬 결과를 비교한다. 새 조회 간 차이를 재정렬 효과로 계산하지 않는다.
- 근거: 선택 자료가 질문의 핵심 개체와 조건에 맞는지 직접 판정한다. BM25·URL 개수·토큰 겹침만으로 통과시키지 않는다.
- 발췌: 원문에서 필요한 문장·숫자·조건·예외가 유지되는지 비교한다. 발췌 길이가 짧다는 것만으로 품질·토큰 절감을 주장하지 않는다.
- 표현: 출처 ID·URL·본문/검색 요약 구분을 유지하고 실제 UTF-8 바이트 한도를 검사한다.
- 내장 검색 비교: 같은 검색어로 관찰된 URL·핵심 정보의 확보 여부를 비교한다. 내장 검색은 정답 목록 전체가 아니고 검색엔진·색인·쿼리 변환·재정렬 내부를 통제하지 못한다. 같은 Bing 결과라고 가정하지 않는다.

034의 공개3질의는 일반 품질 통과가 아니다. 춘천·Python은 반복 조회에서도 후보 부족이 남았고, 강릉도 조건 충족·본문 발췌 품질이 미검증이다. 현재 파이프라인의 기계적 검사와 목표 검색 품질은 구분한다. 연구일지034를 참고한다.
