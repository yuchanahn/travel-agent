# 지식노트

연구일지는 “무엇을 실행했나”, 지식노트는 “다음 작업에도 무엇을 알아야 하나”를 기록한다. 제품의 사용자 메모리 RAG와 별개인 개발용 Markdown 지식이다. 자동 검색·주입 기능을 구현한 것은 아니다.

| 노트 | 읽을 때 |
| --- | --- |
| [현재 상태](current-state.md) | 매 작업 시작, 설정·평가·방향이 충돌할 때 |
| [근거와 평가의 함정](evidence-and-evaluation.md) | 모델·검색·압축·품질을 구현하거나 설명할 때 |
| [연구 기록 정책](research-policy.md) | 연구일지·Notion 작성과 기술 설명 전 |

## 작성과 갱신

한 노트에는 하나의 재사용 가능한 주제만 담고 `kebab-case.md`로 이름 붙인다. 위 표에 연결한다. 노트 수를 채우려고 기존 문서를 복제하지 않는다. 기능 사용법은 원래 기능 문서, 설계 결정은 ADR, 실행 질문·답변·로그는 연구일지에 남긴다.

새 노트는 아래 형식을 따른다. 상태는 `적용 중`, `가설`, `폐기` 중 실제 상태를 적는다. 검토일은 내용과 근거를 실제 확인한 날짜다. 근거 없이 상태만 최신으로 바꾸지 않는다.

```markdown
# 주제

상태: 적용 중
검토일: YYYY-MM-DD
근거: 관련 소스·함수·기준 커밋 또는 연구일지 링크

## 다음 작업에서 사용할 판단
확인한 사실과 적용 조건.

## 근거와 한계
실행 환경·검증 범위·반례·아직 모르는 것.
```

관련 코드·조건이 바뀌면 원근거를 다시 읽고 해당 노트를 갱신한다. 바뀐 판단은 새 근거로 연결하고 과거 실험 결과를 지우지 않는다. 세션 인수인계는 계획 파일에 쓰고 계속 유효한 판단만 노트에 남긴다.

`history/`는 보존 자료다. [재구성 전 AGENTS](history/2026-10-25-agents-before-harness.md)는 자동 적용 지침이 아니며 오래된 “현재” 문장을 새 지시로 해석하지 않는다.
