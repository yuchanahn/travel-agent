# 연구 기록 정책

상태: 적용 중
검토일: 2026-10-25
근거: 재구성 전 AGENTS.md의 연구 기록 지침. 본문 지침을 그대로 분리했다.


외부 라이브러리는 README의 기능·성능·탐지 회피 주장을 사실로 확정하지 않는다. 실제 소스·이슈·PR·변경 이력을 조사하고 원본 사용법과 우리 어댑터를 나눠 실행한다. 특정 엔진의 실패를 라이브러리 전체 실패로 일반화하지 않으며, 다른 엔진의 성공을 요청한 엔진의 수리로 표현하지 않는다.

사용자는 RAG의 BM25·하이브리드 검색·리랭킹을 직접 구현하고 학습하는 것도 명시적인 프로젝트 목표로 정했다. 최소 제품 효율만을 이유로 이 실험을 생략하지 않는다. 이후 도입 이유를 대화·조사 원본 메모리로 확정했다. 요약과 원본을 분리하고 현재 문맥에서 빠진 과거 근거를 검색한다. 006은 초기 후보 검토 이력이며 현재 실행 절차와 범위는 docs/memory-rag.md를 따른다. 모델별 대화 재량을 고정 질문 대본으로 대체하지 않는다.

사용자는 이 프로젝트의 의미 있는 작업을 노션 연구일지에 계속 기록하도록 요청했다. 구현·실험·결정 단위로 docs/research/에도 근거를 남기고, 연결된 Notion 도구로 허브 아래에 기록한다. 도구가 없거나 실패하면 로컬 기록을 남기고 미동기화 상태를 명시한다. 기록 규칙과 허브 URL은 docs/research/README.md를 따른다. 새 허브를 중복 생성하지 않는다.

측정되지 않은 비용 절감·품질 향상을 사실처럼 쓰지 않는다. 가상 데이터와 실제 조회, 기능 동작과 품질 통과, 제안과 구현을 구분한다. 사용자 개인 대화·비밀정보·원본 로그를 공개 Git에 넣지 않는다.

기술 구현을 기록할 때 실제 소스에서 가져온 코드 조각과 구조·데이터 흐름 다이어그램을 함께 넣는다. 코드의 파일·함수와 기준 커밋을 밝히고, 각 조각이 왜 필요한지 설명한다. 의사 코드를 실제 구현처럼 쓰지 않는다. 구현 설명을 요청받으면 실행 경로·함수별 역할·입출력·검증 범위·현재 한계까지 설명한다. 코드가 없는 정책 변경은 억지 코드 대신 관련 설정·문서 변경을 보여준다.

연구일지는 사람이 읽는 문제 해결 기록으로 쓴다. 먼저 테스트 상황을 설명하고, 실제로 보낸 질문을 노션 콜아웃 박스에 넣고, 바로 아래에 그 질문의 실제 답변을 둔다. 초기·개선 답변은 같은 질문으로 비교하고, 다른 질문의 실험에는 질문을 다시 명시한다. 답변은 기록된 문자열 그대로 보여주되 JSON 래퍼와 이스케이프 대신 읽을 수 있는 대화문으로 제시한다. 이어 문제 분석·연구 과정·해결·결과와 추가 비용·남은 한계를 설명한다. 본문에 산출물 경로·종류·SHA-256·원문 무변경 선언 같은 감사 보고서 문구를 넣지 않는다. 원본 로그는 내부에 보존하고, 꼭 필요한 실행법·코드·상세 조건은 별도 상세 영역에 둔다. 좋은 답변의 기준을 먼저 정하고 실제로 실행하지 않은 답변이나 품질 향상을 만들어내지 않는다. 개발 환경·정책 기록은 개발 요청과 결과로 설명한다. 공개 문서에는 합성·비민감 사례만 사용한다.

도구를 사용한 실험을 노션에 기록할 때 실제 툴콜 로그를 기본 접힌 토글로 함께 남긴다. 도구 이름·호출 ID·실제 인자(검색어 포함)·결과 또는 오류·실행 순서와 시간을 연결한다. 모델이 요청한 내용, 실제 도구 실행, 다음 모델에 전달된 결과를 구분하고 필요하면 HTTP 상태와 실제 선택 엔진도 기록한다. 비밀정보·개인 대화·인증 헤더·쿠키는 제외하거나 마스킹하고 그 사실만 짧게 밝힌다. 원본 전체는 비공개로 보존하고 공개 문서에는 비민감 로그만 발췌한다. 도구 호출이 없는 실험에는 없었다고 적고 로그를 만들지 않는다.
