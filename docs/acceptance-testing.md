# 여행 준비 완료 흐름 테스트

완료 범위는 조건 확인→숙소·관광지 조사→예산 변경 반영→출처와 미확인 항목을 포함한 최종 비교다. 예약·결제는 범위에 넣지 않는다. questions는 examples/acceptance-journey.json의 공개 합성3턴이며 실행기는 특정 검색어나 도구 호출을 미리 심지 않는다.

## 실행

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_acceptance.py --output data/private/acceptance/new-phase
# 저장된 실행을 다시 판정한다. 새 모델·검색 호출 없음.
.\.venv\Scripts\python.exe scripts/evaluate_acceptance.py --check-report data/private/acceptance/new-phase/report.json
```

같은 output은 덮어쓰지 않는다. 예제 날짜는2026-11-14~15로 고정했으며 향후 재사용할 때 미래 날짜인지 확인한다. 비교 실험에서는 같은 질문·날짜를 사용한다. 서버는50733을 사용하며 배포는 restart_web.ps1으로 한다.

## 판정

- mechanical_gate: 모든 턴의 실행 완료·답변 존재·같은 대화 유지, 날짜 미정 단계의 숙소 날짜 조회 여부, 날짜 확정 단계의 실제 MCP 인자 일치, 테스트 대화 삭제 여부를 확인한다. 웹 요약에서 임의 가격을 만들어낸 문제는 이 검사만으로 검출하지 못한다.
- manual_review: 저장된 실제 도구 결과와 답변을 비교해 지역·가격 적용 조건·시설·추가요금·취소규정·우천 대안·최신 예산·출처를 검토한다. 모델 판정 점수로 자동 대체하지 않는다.
- release_gate: 기계 검사와 명시적인 근거 검토 pass가 모두 필요하다. pending과 fail은 종료 코드1이다. JSON에 pass를 써 넣는 행위가 근거 검증을 대신하지 않는다.

각 턴의 질문·답변·호출 인자·결과·시간·토큰 지표·비공개 원본 trace를 기록하고 finally에서 자신이 만든 테스트 루트만 삭제한다. 실행 중이거나 삭제 실패하면 cleanup 오류가 남고 승인되지 않는다. 일반 사용자 대화는 건드리지 않는다. 원본 평가 자료는 data/private 아래에 두고 공개 Git에는 넣지 않는다.

## 068 실제 결과

초기3턴은 completed/completed/model_error(HTTP502), 보완3턴은 모두completed였다. 보완본은 기계 검사를 통과했지만 수동 근거 검토는fail이다. 날짜 미정 가격 추정·가격 조건 확인 과장·후보 간 시설 혼합·지역/이동시간 단정이 남았다. 승인된 완성 제품으로 보지 않는다.

첫 단계에서 초기 모델은 임의11월1~2일을 조회했다. 보완 모델은 그 날짜 조회를 하지 않았지만 웹 가격을 예상 견적처럼 제시했다. ‘임의 날짜 MCP 호출 없음’과 ‘올바른 날짜 확인 응답’은 다르다. 두 실행 사이 외부 자료와 모델 응답은 고정하지 않았고 프롬프트·패킷·HTTP 복구를 함께 바꿨으므로 개별 변경의 품질 효과를 분리 입증하지 않는다.

세션은 각3개 실행씩 총6개 삭제했다. 새 JSON-LD 주소 추출과 링크 렌더링은 저장 자료를 사용하는 별도 검사이며, 보완 여행3턴 전체를 그 뒤 다시 실행한 것은 아니다. 상세 질문·실제 답변·도구 로그는068 연구일지를 따른다.
